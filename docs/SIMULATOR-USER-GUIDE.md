# Resim 模拟器使用文档

本文面向使用 Resim 建立芯片架构、检查布局、估算资源并保存结果的用户。当前程序版本为 0.12.x，工程采用独立的芯片架构 YAML 与工艺 YAML。

## 1. 程序和工程位置

Resim 的运行程序位于 `Resim/app/`：

- `Resim.exe`：Windows 主程序，负责启动服务、打开页面和调用系统文件夹选择功能。
- `Resim.Engine.exe`：计算引擎，负责输入校验、资源评估、自动分区与布局以及结果导出。
- `启动Resim.cmd`：双击启动入口。

用户工程默认位于与 `Resim` 同级的 `ResimProjects`。不要把工程或运行结果放进 `Resim/app`，更新程序时可能整体替换该目录。

## 2. 启动模拟器

推荐直接双击：

```text
Resim/app/启动Resim.cmd
```

也可以运行 `Resim/app/Resim.exe`。程序默认使用本机地址和 8770 端口，并自动打开浏览器。若端口已被占用，应关闭旧的 Resim 进程后重试。

## 3. 工程目录

一个标准工程包含：

```text
工程目录/
├─ project.json
├─ inputs/
│  ├─ chip-architecture.yml
│  └─ technology.yml
├─ references/
├─ runs/
├─ README.md
└─ run.ps1
```

- `project.json` 保存工程 ID、显示名称和两份输入文件的位置。
- `chip-architecture.yml` 描述 die、core、模块、端口、连接、初始布局、预留区、堆叠和搜索约束。
- `technology.yml` 描述工艺、金属层、标准单元参考、TSV、混合键合及估算参数。
- `references/` 保存工程来源和辅助资料，不作为模拟输入自动读取。
- `runs/` 保存每次评估或寻优的输入快照、元数据和结果。

不要把 `architecture.yml` 等旧单文件输入继续作为正式入口。当前工程统一使用上述两份新版 YAML。

## 4. 输入与校验

架构文件和工艺文件使用不同的 `schema_version`：

```yaml
schema_version: resim-architecture/1
```

```yaml
schema_version: resim-technology/1
```

页面会在预览或计算前把两份输入合并成内部运行模型。校验主要检查：

- ID 是否唯一；
- die、core、模块、端口和连接引用是否存在；
- 坐标、尺寸和单位是否合法；
- 模块是否越界或在同一 die 上重叠；
- TSV/HB 接口是否连接相邻层并符合 die 朝向；
- 固定模块、预留区和资源参数是否相互矛盾；
- 未知面积、功耗、延迟或容量是否被明确保留为未知量。

输入格式的机器可读定义位于 `docs/contracts/`。

## 5. 页面工作流程

### 5.1 架构输入

选择已有工程，或新建、复制工程。分别导入架构 YAML 和工艺 YAML，也可以在页面中编辑 die、模块、连接、工艺与布局约束。

“应用”只更新当前草稿和预览，不会自动生成历史运行记录。

### 5.2 布局规划

用于查看整颗芯片、单个 core 或单层 die。可以选择模块、修改 die 和坐标、拖动模块，以及运行自动分区和布局。

自动规划必须遵守模块边界、固定模块、间距、预留区和同层不重叠约束。生成的候选仍需要经过资源与可实现性检查。

### 5.3 连接与布线

用于检查模块之间的逻辑连接、位宽、端口、数据路径、估算线长、金属层使用和跨层接口。逻辑位宽不等同于物理并行线数或传输速率。

### 5.4 资源与计算

按 die 查看面积、布局利用率、布线与拥塞、TSV/HB、功耗与供电。缺少工艺或活动率时，结果显示为未知，不应把未知值当作零。

### 5.5 实现难点

集中显示错误、风险和待补数据。项目能够打开或完成计算，不代表已经通过物理实现检查；应分别处理越界、重叠、容量不足、朝向冲突和未知参数。

### 5.6 结果管理

“保存评估结果”会在 `runs/` 下创建独立目录。每条记录保存当时的输入快照，因此修改当前工程不会覆盖旧结果。

结果管理中的两个下载选项都是可选的：

- **下载 JSON**：导出完整机器可读评估报告，包含汇总指标、逐 die/模块资源、连接、问题和计算依据。适合脚本分析、结果对比或接入其他工具。
- **下载布局 YAML**：导出当前方案的布局与输入表示，适合重新导入、复制方案或继续调整位置。

如果只在 Resim 页面内查看并保留 `runs/` 历史，这两个下载按钮都可以不使用。删除按钮也不会影响模拟器内部计算。

## 6. 3D 堆叠显示

- 模块实体位于所属逻辑 die 的正面布局平面。
- TSV 表示穿过硅层的垂直连接资源；HB 表示直接键合接口。
- 不同金属层可以使用不同颜色显示，颜色只表示观察分类，不改变计算。
- 单层正面和背面是观察方式，不会自动镜像或重排输入坐标。
- DRAM 可以作为抽象平台显示；若没有内部模型，不计算其内部标准单元面积和功耗。

## 7. 命令行使用

在工作区根目录可运行工程自带脚本：

```powershell
.\ResimProjects\工程ID\run.ps1 -Action validate
.\ResimProjects\工程ID\run.ps1 -Action evaluate
.\ResimProjects\工程ID\run.ps1 -Action optimize
```

也可以直接调用引擎：

```powershell
.\Resim\app\Resim.Engine.exe validate --projects-dir .\ResimProjects --project 工程ID
```

## 8. 常见问题

### 工程不出现在列表中

检查工程目录名、`project.json`、工程 ID，以及两份 YAML 是否存在。目录名和 `project.json.id` 必须一致。

### 工程输入有效但页面打不开

检查最新 `runs/<运行ID>/run.json` 是否指向已删除的外部结果目录。悬空的已完成记录会导致页面读取最近结果失败。

### 中文在终端显示乱码

这通常是 Windows 控制台编码问题，不代表 UTF-8 YAML 或网页内容损坏。以文件的 UTF-8 内容和网页显示为准。

### `.resim-store.lock` 能否删除

新版 Windows 程序采用系统命名互斥锁，不再生成此文件。它是旧版遗留的占位锁文件；关闭所有旧版 Resim 后可以删除。并发保存保护仍由程序自动完成。

### `_project-aliases.json` 有什么作用

它把旧工程 ID 映射到新 ID，使旧脚本、缓存和历史链接仍能找到改名后的工程。

## 9. 结果解释边界

Resim 是架构和早期物理规划工具。结果只有在输入参数有明确来源和校准时才具有相应精度。当前输出不能代替详细布线、时序签核、功耗完整性、热分析或制造签核。

已录入图纸资料的模块，可在布局规划中点击模块，展开“图纸参数与参考估算”，查看图示尺寸、子系统面积、单元数、引脚数和来源。参考尺寸不替换当前布局尺寸；当当前占地小于参考资源面积时，“实现难点”会提示调整。子系统合计不会重复算到每个子模块上。

连接只有位宽或线数、没有频率时，传输速度显示“未知”。“连接与布线”中选中连接后，可展开“连接数据依据”查看位数和方向的来源。图纸中尚未明确的线路不会用虚构数值补齐。
