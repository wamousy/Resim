# 架构输入与历史结果

## 页面顺序

架构输入 → 布局规划 → 连接与布线 → 资源与计算 → 实现难点 → 结果管理。

“实现难点”是对当前输入与布局进行资源计算后的结论，按违例、风险、待补数据汇总，可定位到布局中的问题对象。已移除页尾“模型边界与开源来源”栏；具体工艺参数的依据仍随输入保留。

## 两种输入方式

**导入 YAML**：先在“定义项目”载入或新建项目，再分别选择芯片架构与工艺库文件，各自应用预览。工程保存时直接维护这两份新版 YAML。导入新芯片时请检查下方工艺库，未重新选择时使用文本框中当前的库。

**自定义**：先“新建项目”，或编辑已载入工程。

- Die 表格：新增/删除层，自定义唯一的 Die ID，设置类型、面积、宽度、高度、厚度和功耗预算。改宽/高时自动更新面积，改面积时保持宽度并更新高度。Die 改名同步更新模块、接口、供电及约束引用；删除仍被引用的层会被阻止。
- 模块表单：新增/删除模块，编辑 Core、类型、所在 Die、允许分配的 Die、尺寸、坐标、功耗、标准单元/硬宏面积、目标利用率、算力/带宽/容量、精度、频率与位宽。新 Core ID 会创建新核。已有模块 ID 不直接改名，保留连接引用；删除被连接引用的模块前需先修改连接。
- 连接表单：设置发送端、接收端、逻辑位宽、带宽、单线速率、物理线数、控制线与冗余。一个条目表示单向连接；双向传输定义两个反向条目。
- 工艺库：独立 YAML 导入或自定义表单，定义金属层方向、线宽、pitch、可用比例与 TSV/键合等参数。

每个表单应用后会重新校验与计算预览，失败时保留原布局与表单修改；应用预览不写入工程。完成后到“结果管理”填写批次文件夹名称和方案名称，点击“保存当前方案”，或选择批量保存。应用单个表单时保留其他表单尚未应用的修改；保存前需先处理所有待应用输入。整体 YAML 与网页表单同时修改时会提示先处理，避免互相覆盖。

工艺库与模块资源缺失不会当成真实零值。功耗留空代表未知；标准单元或硬宏面积留空时 area_known=false。显式填写 0 则是已知零值。模块外框尺寸与真实资源面积分别输入。

## 两类 YAML

芯片架构文件 `chip-architecture.yml`：

```yaml
schema_version: resim-architecture/1
name: 我的芯片
architecture:
  # chip、dies、cores、modules、links、metrics 等
constraints:
  # 利用率、间距、通道、电压域、接口约束等
floorplan:
  # placements、tsv_regions、supply_ports 等
search:
  # 寻优目标及搜索预算
```

工艺库文件 `technology.yml`：

```yaml
schema_version: resim-technology/1
resources:
  technology: 工艺标识
  technology_provenance: 工艺参数来源
  routing_availability: 0.15
  metals:
    - name: M2
      direction: HORIZONTAL
      width_um: 0.1
      pitch_um: 0.2
      availability: 0.15
  tsv: null
  notes: []
```

以上只说明结构，其中工艺数值为格式示意；可直接导入的完整示例位于 `../ResimProjects/_templates/split-yaml/`，来自本地 GCD16 / Nangate45 工程。实际数值以所选库及其来源为准。

芯片架构文件不含 resources；工艺库文件不含 architecture、floorplan。各字段单位写入名称：尺寸/坐标 µm，资源面积 µm²，功耗 W，带宽 GB/s，单线速率 Gbit/s。Die 表格显示 mm 与 mm²，并转换为内部 µm。

页面可以分别下载两类 YAML。工程目录只保存这两类新版输入。模拟引擎运行前在内存中合并，历史目录仍存储当次**合并后的完整快照**，使旧运行记录可以复现；“高级完整输入”仅用于查看运行时合并内容。这里的工艺库是 Resim 资源参数 YAML，不是直接读取任意厂商 PDK/LEF/Liberty 的入口。

## 历史查看与对比

结果管理保留当前结果路径、布局图、资源报告及历史载入；不再单独提供下载 JSON 或布局 YAML 按钮。“历史结果对比”默认收起，点击后显示选择器：

1. 默认两个对比位置，通过“添加方案”或“移除”自定义对比数量（至少两个）。
2. 每个位置独立选择工程、历史运行及候选；可以跨运行、跨工程，也可以比较同次寻优的不同候选。
3. 点击“开始对比”后并列显示各方案指标，不设基线，不默认计算某个方案相对另一个的增减。
4. 模块布局差异与约束问题分布点击后展开；每列对应一个所选方案。
5. 可打开各方案完整报告，或下载包含所选方案来源及全部比较数据的 `resim-comparison/2` JSON。

同一历史方案不可重复选择。增减方案或切换选择会清除旧对比，须重新点击“开始对比”。寻优中的原始参考布局不加入候选对比列表；未产生候选的运行会显示“无候选方案”。旧结果文件保留。

比较直接使用当时保存的计算结果，不重新计算、不修改当前布局。缺失指标显示“未知”；计算版本、工艺库参数不同会提示比较条件变化。资源数值不自动等于方案优劣。问题按严重级别、代码、对象匹配并去重；页面明细最多列 100 个对象，JSON 含全部数据。失败运行不作为有效比较输入。

项目文件夹可在新建时自定义。明确保存时才在项目内创建批次文件夹，其下各方案独立存储；网页寻优只生成候选预览，旧记录及目录保持不变。历史列表按批次分组，可任意选择其中方案进行比较。

## 当前页面入口

1. 定义项目：整个栏目可展开或折叠，折叠不清除草稿。下拉框只列真实项目，无“选择已有项目”占位项；没有项目时显示不可载入的空状态。项目名称和保存位置默认隐藏，点击“新建项目”才展开；点“收起”保留填写内容。项目名称用于显示，保存位置是独立选择的完整文件夹路径，两者互不命名。载入项目或首次保存成功后收起创建项。
2. 架构输入与布局约束：点击展开，选择导入芯片架构 YAML 或自定义 Die、模块、连接及间距约束；应用后更新预览。
3. 工艺库与连线资源：点击展开，选择导入工艺资源 YAML 或自定义金属层、布线可用比例、默认 TSV/键合参数；应用后更新资源评估。

两种工艺输入方式切换时同步未应用内容，恢复按钮撤销本表单修改。单金属层可用比例为空表示继承全局值，0 表示关闭该层自动分配。表单会拒绝重复层名、非正尺寸、线宽超过 pitch、越界比例等输入。未展示的 delay_model、notes 等参数保持原值。接口自身已有的独立 TSV 参数仍按接口定义执行；全局工艺参数不会替换专有接口配置。

“保存评估结果”会写入当次输入、布局及报告；预览只在内存更新。自动寻优在布局页填写正整数候选数量，不设固定个数上限；受约束和时间预算影响，实际方案数可能更少。只在求解器确认当前离散空间已穷尽时说明全部数量，超时不声称已找到最大数量。候选横向排列，可用滑块浏览。历史查看及跨方案比较在结果管理中进行。

## 项目文件夹与结果子文件夹

新建项目时，“项目名称”是项目列表中的显示名称，不用于创建或重命名文件夹。在“项目保存位置”填写完整路径，或选择/新建一个空文件夹。所选文件夹本身就是项目目录，不会再按项目名称创建子文件夹；留空则在默认位置生成与显示名称无关的 project-随机编号目录。首次保存后，架构、工艺、项目配置和结果均在其中。

项目列表直接扫描 `ResimProjects` 下一级文件夹中的 `project.json`，不要求文件夹名与内部项目编号一致，支持中文名称和文件夹改名。自定义保存位置不再产生额外的 `project-编号/_project-location.json` 登记目录，也不生成统一项目索引文件。

其他位置的项目通过“定义项目 → 打开项目文件夹”载入，选择包含 `project.json` 的文件夹。程序读取该项目自身的输入与历史，不复制项目；打开后加入本次运行的列表。外部路径只保存在运行内存中，关闭并重新启动程序后需要重新打开。取消选择不改变当前项目；存在未保存修改时先提示处理。旧登记文件仍兼容读取，同一项目去重显示；仅含登记文件且指向默认目录下项目的旧空壳目录可在确认目标完整后移除。

结果管理中分开填写“批次文件夹名称”和“当前方案名称”。同次寻优的候选属于一个批次，各自保存到其中独立的方案子文件夹。例如项目目录为 `D:\芯片项目`：

```text
D:\芯片项目/
├─ project.json
├─ inputs/                 架构与工艺 YAML
├─ 第一次布局探索/         自定义批次文件夹名称
│  ├─ run.json             批次输入哈希、搜索配置、版本及已保存方案清单
│  ├─ 低拥塞方案/          与所有同批次方案使用一致结构
│  │  ├─ inputs/          本方案的 chip-architecture.yml 和 technology.yml
│  │  ├─ floorplan.svg    各层布局图
│  │  ├─ implementation-difficulties.md
│  │  ├─ report.html      可阅读的资源报告
│  │  ├─ resource-report.json   用于历史恢复与比较
│  │  └─ run.json         方案名称、来源及校验信息
│  ├─ 短连线方案/          同批次的另一个方案
│  └─ 低拥塞方案调整版/    手工派生方案，保留原方案关联
└─ 第二次布局探索/         新一次寻优或输入变化后的批次
```

项目文件夹只在新建时指定，已有项目保存结果时不能改换归属。浏览/创建空文件夹不触发模拟，自动寻优只生成预览。旧版本外置结果仍从原位置读取，不自动搬迁；新保存结果进入当前项目目录。

项目根目录的 `inputs` 存放项目输入 YAML。每个方案另有独立 `inputs`，保存实际评估时的架构（含分区、坐标、约束和搜索配置）及工艺。`run1`、`第一次布局探索` 等批次目录只含方案清单与各方案，不再放共享 inputs。`project.json` 和各级 `run.json` 是恢复项目、分组、命名及派生关系所需的元数据。

新版网页不再生成 `runs` 与 `_batch-index` 两个重复索引目录，直接读取实际批次及方案的 `run.json` 来查找历史。旧项目如已有这些目录仍兼容读取；其中 `runs` 可能含旧版真实结果，不能一概删除。旧 API/CLI 持久化调用仍可能使用原 runs 布局。

## 候选等待与结果命名

网页自动分区与布局显示独立任务状态：准备输入、搜索并复核、完成或失败，并显示真实耗时。求解预算不是整个请求的严格完成时限，准备与评估可能另外耗时；不使用推算百分比。运行期间禁止重复提交和修改输入，可以切换工作空间。关闭页面不代表后端任务取消。

寻优调用无写入的 `/api/optimize/preview`。候选只保留在页面内，生成完成不自动写历史。结果管理提供三种保存方式：

1. **保存当前方案**：只保存布局窗口正在查看的方案，包括已经完成重算的手工修改。当前方案名称可自定义，留空使用候选名称或“手工调整方案”。
2. **保存选中方案**：展开候选列表，勾选要保存的候选，并分别修改名称。
3. **保存全部候选**：保存本次寻优中尚未保存的全部候选。当前手工修改稿或“寻优前布局”不属于自动候选，需要用“保存当前方案”。

批次名称首次保存时填写，保存后锁定；追加方案自动进入同一批次。批量保存显示逐方案进度；如果中途失败，已完成的方案保留，重试只处理未完成项。保存不会切换正在查看的方案，也不会清除剩余候选。相同批次中已保存的相同布局不重复创建。未保存候选在关闭或重新载入页面后会丢失。

**每个方案保存什么：** 两份 inputs YAML、`floorplan.svg`、`implementation-difficulties.md`、`report.html`、`resource-report.json` 和 `run.json`，共七个文件。布局 SVG 可单独打开，包含各层尺寸、模块、禁布区、TSV 预留区和 HB 接口提示；它是架构级布局图，不是 GDS 或详细布线。网页结果区新增“查看布局图”。HTML 供阅读，JSON 供历史恢复与比较，JSON 不再内嵌一份重复架构，而是引用相邻 inputs。当前相机位置、选中对象及 3D 截图不保存。

不再自动生成重复的 `input.yml`、`resolved-input.yml`、`layout-plan.yml`、`implementation-difficulties.json`、`output-manifest.json`。分区和坐标已在本方案架构 YAML 中；通过“打开结果文件夹”可取得本方案的双 YAML 和资源 JSON。结果管理不再额外提供 JSON / 布局 YAML 下载按钮，正常保存、历史查看和比较不受影响。读取历史会核对方案输入哈希，输入被改动后拒绝把它与旧指标混合展示。各方案可独立复制并重新评估。

**批次如何区分：** 重新执行自动寻优会产生新批次；架构、工艺、约束或搜索配置变化后也建立新批次。仅修改 `floorplan.placements` 可作为同批次的新方案。批次通过配置哈希校验同组关系，各方案存自己的实际评估输入，不额外备份未保存的搜索前布局；若需要保留它，请选择“寻优前布局”单独保存。派生方案保留父来源；未保存的父方案不会被自动保存。

新批次使用上述精简结构。已有旧批次继续可读，向旧批次追加时沿用该批次原格式，确保同批次方案一致；不自动改写已保存结果。再次执行寻优会使用新结构。

完整 YAML、网页表单或 Die 表格有未应用修改、预览正在计算或计算失败时，三种保存操作均被阻止。先应用或重试预览，再保存。后端重新计算并核对预览标识，不接受过期预览。

批次与方案名称支持中文和空格，最多 120 个 UTF-16 单元；路径分隔符、Windows 禁用字符/设备名及句点结尾会被拒绝。不同方案或批次重名时，实际目录自动追加 ` (2)`、` (3)`；项目保留目录也自动避让，不覆盖原内容。页面显示实际路径。旧独立结果不搬迁、不重命名。历史记录显示方案名，时间、模式和编号在“记录信息”中查看。
