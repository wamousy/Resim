# Resim 资源模拟器使用与开发交接文档

更新日期：2026-09-29。发布与引擎版本统一为 **0.12.0**；运行输入版本保持 `resim/0.1`（新增可选原生 `stack` 字段），两类输入文件版本保持 `/1`。旧版 0.11.0 历史结果原样保留。当前变更尚未提交 Git。

程序校验信息、环境与自动检查结果见 [verification.json](verification.json)，原始测试记录见 [verification.tap](verification.tap)。后续接手时应重新运行检查，不将本次结果当作所有未来版本的保证。

## 1. 交接结论

Resim 当前可作为**架构阶段资源估算和三维布局规划工具**交付试用。核心目标是识别当前架构的实现难点，并辅助架构与前后端人员讨论模块分区、Die 归属和 floorplan。

已形成“架构与工艺输入 → 布局编辑或自动寻优 → 资源计算 → 实现难点 → 保存及历史对比”的闭环。最新自动检查结果以本目录 `verification.json` 为准，包含前端与程序集成回归、完整 Python 核心/API/存储测试、源码与构建清单核对。

交付时必须同时说明以下边界：

- **不能承诺实际芯片可实现或物理全局最优。** 布线、TSV、功耗与延迟均受输入完整度和估算模型限制。
- **后端源码缺口已补齐。** 从本地开发记录恢复了 18 个后端模块与 12 份原测试源码，保留恢复校验依据；已提供锁定依赖和无需旧引擎的完整构建。见 [开发指南](DEVELOPMENT.md) 和 [恢复证据](source-recovery.json)。
- **BLX 示例主要验证布局和接口预算。** 功耗、TSV 工艺及细分模块互联存在缺失，示例上的零布线面积不能理解为实际芯片无需布线。

当前既可供架构人员探索，也可从源码继续维护。另一台 Windows 机器仍需按开发指南复建验收；物理模型精度需要真实工艺和后端样本校准。

## 2. 功能清单与完成程度

| 能力 | 当前实现 | 边界 / 后续工作 |
| --- | --- | --- |
| 项目管理 | 新建、复制、命名、载入独立工程 | 本地单用户工作流；不提供协同权限与多人编辑冲突处理 |
| 双 YAML 输入 | 芯片架构、工艺资源分别导入、保存、下载 | 工艺 YAML 是 Resim 参数格式，不是任意厂商 PDK 的直接导入接口 |
| 网页自定义 | Die、模块、连接、面积、功耗、利用率、金属层等 | 部分高级约束及新增接口区域仍需 YAML |
| 数据校验 | ID、引用、尺寸、数值范围、原生 stack；离线双文件检查 | 新评估的 Web / CLI / JSON / HTML 共用引擎堆叠检查；旧结果只做只读兼容 |
| 三维布局 | 堆叠、展开、单层、正反面、整体/单 Core、旋转/平移/缩放 | 视觉高度、线宽及 TSV 柱数为示意，不是制造尺寸模型 |
| 交互规划 | 选中对象详情、模块拖动、坐标修改、跨层迁移、撤销/重做 | 受允许 Die、固定模块等约束限制；已有模块不自动切割 |
| 连接展示 | 单向逻辑连接、方向、位宽/带宽、金属实现、Core 内/间区分 | 双向需两条有向连接；不是详细布线网表 |
| 资源评估 | 面积、占用率、预留、供电预算、TSV/HB、线长、金属面积、逐层拥塞 | 是架构级近似；不能代替布局布线签核 |
| 实现难点 | 违例、风险、缺失数据、原因、建议及对象定位 | 建议以规则解释为主，尚无完整自动修复闭环 |
| 自动分区与布局 | OR-Tools CP-SAT 为模块选择 Die 与坐标；多候选、去重、资源复核 | 保持模块长宽、TSV 区和供电端口固定；不拆分模块，不执行 RTL/netlist partition |
| 历史与结果 | 每方案独立双 YAML、精简结果文件、布局 SVG、选中/全部候选保存、派生关系、重复请求复用；直接读取批次清单；便携工程包 | 批量失败保留完成项；断电清理和任务续算仍待完善，目前本地单用户工作流 |
| 多方案对比 | 自定义方案数量，跨运行/跨工程/候选对比 | 按模块 ID 对齐；尚不自动判断因果或给出综合最优方案 |
| 性能/热/电气签核 | 未实现 | 不模拟大模型运行性能；无温度求解、STA、IR drop、EM、DRC/LVS |

“自动分区”在本版特指**现有模块的 Die 分配**。不要向使用方描述为可以任意切分一个模块或自动生成前端 RTL 分区。

## 3. 安装、目录与启动

### 3.1 目录分工

```text
arch/
├─ Resim/                           仓库；运行、源码、资料和测试分开
│  ├─ app/                         可独立分发的运行程序
│  │  ├─ Resim.exe / Resim.Engine.exe
│  │  ├─ 启动Resim.cmd             双击打开页面
│  │  └─ _internal/                运行依赖及前端发布副本
│  ├─ src/                         源码与开发配套
│  │  ├─ frontend/                网页、三维、样式和前端依赖
│  │  ├─ backend/                 完整 Python 后端与 desktop/ResimHost.cs
│  │  ├─ tests/                   frontend、backend、integration、fixtures
│  │  └─ tools/                   开发、构建、验证与发布；恢复证据在 recovery
│  └─ docs/                        使用交接说明、契约、验证记录
└─ ResimProjects/                  独立用户工程和示例
   ├─ <project-id>/
   │  ├─ project.json
   │  ├─ inputs/chip-architecture.yml
   │  ├─ inputs/technology.yml
   │  └─ <批次名称>/<方案名称>/     新版网页结果；旧项目可能保留 runs
   ├─ _references/                 示例工艺原件、来源、哈希
   └─ _templates/                  示例输入模板
```

Resim 只保留 app、src、docs 三个业务目录；根目录的 `.git` / `.gitignore` 属于版本管理元数据。测试与工具跟随 src 交接，说明文件统一放在 docs。原字节码保存在 `src/tools/recovery/`，仅作恢复证据；运行与测试不依赖它。

新建时可自定义完整项目目录，新版网页结果按“项目 / 批次 / 方案”存储。旧独立结果及外置结果不搬迁，使用页面实际路径和 `run.json`，不要自行拼接历史位置。跨机器交接可用 `pack-project` 收集工程及结果，再用 `unpack-project` 校验、保留批次与派生关系并重定位路径；命令见 [本次实施与迁移说明](RELEASE-0.12.md)。只复制 app 即可运行，不依赖 src 和 docs。

项目发现不需要独立索引：扫描默认目录下一级文件夹中的 project.json，支持文件夹名称与项目编号不同。外部项目在“定义项目 → 打开项目文件夹”中打开，只在本次服务内存中记录路径，重启后重新打开。后端 server.get_store 按根目录复用会话实例；workspace.ProjectStore._opened 仅是内存状态。新建不再生成 `_project-location.json` 登记目录；旧登记与别名文件兼容读取。重复项目编号会明确报错，不静默选择其中一个。搬迁后的项目内结果路径根据实际目录解析，历史文件不重写。相关回归为 test_project_discovery.py、test_project_folders.py、test_batches.py、open-project.test.mjs 和 output-folders.test.mjs。

### 3.2 环境

运行发布包使用 Windows x64 和支持 WebGL 的浏览器；所需 Python、计算依赖随 `_internal` 提供，不要求使用人员单独安装 Python。`Resim.exe` 入口使用 Windows .NET Framework。

开发检查使用 Node.js；本次实际验证环境为 Node `v24.19.0`。源码开发与完整构建需要 Python **3.13**，本机验证为 3.13.9；依赖固定于 `src/backend/requirements-lock.txt`。未经测试不能直接换用其他 Python 主/次版本。

### 3.3 启动

双击 `app/启动Resim.cmd` 或 `app/Resim.exe`。也可在 Resim 目录打开 PowerShell：

```powershell
.\app\Resim.exe serve --port 8770 --projects-dir "..\ResimProjects" --open-browser
```

页面地址为 `http://127.0.0.1:8770/`。必须通过 `Resim.exe` 启动完整 Web 功能；直接启动 Engine 不包含目录浏览/创建服务。不要只复制单个 exe，不要删除 `_internal`。

程序定位是本机工具。未完成网络服务的身份认证、访问控制、任务配额和多用户隔离设计，不应直接作为共享远程服务部署。

## 4. 使用人员操作流程

1. **定义项目。** 在“架构输入”载入已有项目，或新建项目并命名；选择整个项目的文件夹，需要时新建文件夹。
2. **提供架构。** 展开架构输入，选择导入 YAML 或自定义；确认 Die 数量、尺寸、朝向、模块及连接。Core 数量由架构成员定义，不是视图选项决定。
3. **提供工艺资源。** 独立导入或编辑工艺 YAML；核对线宽、pitch、方向、可用比例、TSV 参数及来源。更换架构不会自动替换仍在使用的工艺库。
4. **应用并预览。** 处理各表单待应用修改。预览会重算资源，但不生成历史记录。校验失败时根据错误修改输入。
5. **规划布局。** 查看整体/单 Core/单层，点击对象看详情。移动模块或跨层迁移后，等待预览重新计算完成。
6. **查看资源。** 总览中选择 Die，再按面积、布线、TSV/HB、功耗供电查看明细；公式和原始明细按需展开。
7. **检查实现难点。** 分别查看违例和待补数据，定位对象。没有违例但存在缺失数据时，不能确认可行。
8. **按需自动寻优。** 填候选数并执行；每个候选分别复核。候选数没有固定人为上限，但受时间和可行空间约束。
9. **保存及比较。** 到“结果管理”填写批次文件夹名称及方案名称，保存当前、选中或全部候选。网页寻优生成的候选不会自动落盘；同批次各方案独立保存，历史按批次分组，可打开报告、目录或选择任意历史方案比较。

“寻优前布局”是本次搜索启动时的输入布局，不计入候选数。结果保存完成与资源评估通过是两个独立概念：`status=completed` 表示运行完成，并不表示没有违例。

## 5. 输入规范

### 5.1 芯片架构文件

文件名 `chip-architecture.yml`，版本 `resim-architecture/1`。

| 区域 | 主要内容 | 输入责任 |
| --- | --- | --- |
| `name` | 项目显示名称 | 架构负责人 |
| `architecture.chip` | 芯片标识 | 架构负责人 |
| `architecture.dies` | 唯一 ID、顺序、类型、宽高、厚度、电压、预算、最大占用率 | 架构 / 后端 |
| `architecture.cores` | 核 ID、同层要求、各级性能需求 | 架构负责人 |
| `architecture.modules` | 类型、Core、尺寸、允许 Die、面积、功耗、目标利用率、端口、实现配置 | 架构 / 前端 / 后端 |
| `architecture.links` | 发送/接收模块及端口、位宽、带宽、物理线数、冗余、可用金属层等 | 架构 / 互联负责人 |
| `constraints` | Die 面积上限、拥塞上限、同组、间距、禁布区、通道等 | 后端负责人 |
| `floorplan` | 模块坐标、TSV/HB 区域、所属 Core、信号预算、供电端口 | 后端 / 封装负责人 |
| `stack.die_faces` | Die ID → `up` / `down` / `unknown` | 封装 / 后端 |
| `search` | 目标、网格、时间、数量、种子和权重 | 方案评估人员 |

文件包含实际可用布局时可直接评估；自动寻优基于模块和约束生成候选。网页显示尺寸与内部数值的单位不同，导入时不能照搬屏幕上的 mm 数字到 `_um` 字段。

### 5.2 工艺资源文件

文件名 `technology.yml`，版本 `resim-technology/1`，内容仅包含 `resources`。

| 字段 | 作用 |
| --- | --- |
| `technology` / `technology_provenance` | 工艺名称与来源，不能用示例名称代替真实校准 |
| `metals[]` | 层名、HORIZONTAL/VERTICAL、线宽、pitch、可用比例 |
| `routing_availability` | 未独立指定可用比例的金属层使用此默认比例 |
| `tsv` | TSV/键合几何及电流等参数；为空表示未提供 |
| `delay_model` | 可选的平面及层间延迟系数，需注明是否校准 |
| `notes` | 假设、参数依据和限制 |

模块标准单元/硬宏面积及功耗当前放在架构模块中；工艺文件主要提供布线和接口参数。运行时不会从工艺名称自动推导模块面积。CLI 有 `import-lef tech cells --out ...` 辅助入口，但不是完整 PDK、Liberty、多工艺角或签核环境导入器。

### 5.3 单位与数据状态

| 数据 | 内部/文件单位 | 注意事项 |
| --- | --- | --- |
| 长度、坐标、厚度 | µm | 网页 Die 编辑可显示 mm；1 mm = 1000 µm |
| 标准单元与硬宏面积 | µm² | Die 结果常显示 mm²；1 mm² = 10⁶ µm² |
| 功耗 / 电压 / 电流 | W / V / A | TSV 单孔电流参数以具体字段的 mA 标识为准 |
| 逻辑位宽 | bit | 不自动等于实际金属线数或 TSV 数 |
| 带宽 / 单线速率 | GB/s / Gbit/s | 数据线数由显式值或带宽换算；两者须一致 |
| 比例 | 0～1 | 65% 在 YAML 中通常写 `0.65` |
| `null` | 未知 / 未提供 | 不能替换为 0 |
| `0` | 显式已知零 | 例如禁用某金属层可用容量，或确实没有控制线 |

模块外框占地与真实单元面积必须分开。`area_known=false` 表示实际资源面积未知，即使已经画出模块矩形。`target_cell_utilization` 是规划输入，省略时的 65% 是程序默认，不是工艺库强制规定。

单条连接表示单向通路；双向传输用两条反向连接，需确认是否共享实际资源。方案中的 k/K 倍率应在输入中展开成整数，避免“8K”按 8000 或 8192 理解不同。

### 5.4 存储与兼容

工程根目录维护两份独立输入。引擎执行前合并为 `resim/0.1`；历史运行保留当次完整输入快照。现有旧版完整输入可通过网页导入；仅有旧 `inputs/architecture.yml` 的有效工程会在首次读取时迁移为双文件；迁移使用恢复日志，旧运行快照不变。

0.12.0 后端与网页使用正式 `stack.die_faces` 字段。旧 description 兼容块在载入时转为该字段并保留原文字说明；两种输入同时给出且矛盾时拒绝。旧历史快照不批量改写。

格式示意和完整示例入口见 [INPUT-WORKFLOW.md](INPUT-WORKFLOW.md)；朝向细节见 [STACK-MODEL.md](STACK-MODEL.md)。

## 6. 输出规范与查找方法

### 6.1 网页批次及方案

```text
<项目目录>/<批次文件夹名称>/
├─ run.json                       批次 ID、版本、搜索摘要、输入哈希和方案清单
├─ <方案名称>/
│  ├─ run.json                    方案记录 ID、批次/父方案关联及实际路径
│  ├─ inputs/
│  │  ├─ chip-architecture.yml    此方案架构、分区、坐标、约束和搜索配置
│  │  └─ technology.yml           此方案工艺库
│  ├─ resource-report.json        结构化资源、实现难点及计算依据
│  ├─ floorplan.svg               各层静态布局图（非 GDS / 详细布线）
│  ├─ report.html                 静态报告
│  └─ implementation-difficulties.md
└─ <另一方案名称>/                同样的完整独立文件集
```

批次不再保存共享输入，各方案保留独立双 YAML，同批次文件结构一致。新批次格式为 resim-batch/2，单方案 input_layout=per-plan/2。resource-report.json 使用 storage_format=resim-report/2，省去重复 project；ProjectStore.result 根据双 YAML 和输入哈希还原完整 project 后交给网页。plan_files.py 负责独立输入与 SVG，export.save_report(compact=True) 生成精简文件集。旧批次仍按旧格式读取和追加，不混合两套结构。

“保存当前方案”对应正在浏览且完成预览的报告，“保存全部候选”仅含自动生成的候选，不含手工稿或寻优前布局。未保存的初始布局不再在批次目录额外备份，需要时单独保存为方案。仅修改 placements 可作为同批次派生方案；资源、架构、约束或搜索配置变化以及重新寻优均新建批次。重复请求复用原记录，同名不同方案自动增加目录序号。

新版网页直接读取项目内各批次的 `run.json` 和其中列出的方案，不再创建 `runs` 或 `_batch-index` 重复索引目录。旧索引可读并按方案 ID 去重；旧 runs 可能含真实结果，不应直接删除。兼容接口中的 run_id 表示单方案，batch_id 是批次标识。批量保存逐项提交，中途失败保留已完成项，重试继续剩余方案；不宣称整个批次是一个事务。页面相机、选择状态和 3D 截图不持久化。

### 6.2 旧接口和 CLI 兼容布局

旧 evaluate/CLI 默认将 input.yml、resolved-input.yml、run.json 放在运行目录，报告在其 results/；显式 result_folder_name 的报告直接放在命名目录。旧持久化 optimize 继续使用下述结构，新版网页不再调用它：

```text
<实际运行目录>/results/
├─ search-result.json
├─ baseline/                      内部目录名，页面称“寻优前布局”
└─ candidate-1/ … candidate-N/
   ├─ resource-report.json
   ├─ layout-plan.yml
   └─ report.html
```

以已生成目录和 `storage` 为准。历史对比导出的 `resim-comparison/2` JSON 保存所选运行/候选来源、并列指标、布局差异、问题分布；不是新的资源仿真结果。

### 6.3 报告字段

| 字段 | 用途 |
| --- | --- |
| `summary` | 全片汇总、违例数、缺失数 |
| `dies` / `modules` | 每层和每模块的布局、资源、余量 |
| `links` / `routes` / `wiring` | 连接需求、估算路径和线面积 |
| `metal_routing` / `spacing` / `routing_channels` | 独立金属层容量、间距、通道检查 |
| `interfaces` | 每个 TSV/HB 区域的信号、电源、地、容量与余量 |
| `supply` / `ports` / `supply_groups` | 电压域、端口和供电预算 |
| `issues` | 严重级别、代码、对象、原因、建议 |
| `calculations` / `methodology` | 公式、代入值、参数依据、算法与模型边界 |
| `project` | 对应方案的完整输入快照 |
| `storage` | 实际工程、运行与结果位置 |

0.12.0 新报告由引擎统一写入 `STACK_GEOMETRY` 和汇总状态，Web / CLI / JSON / HTML 一致。Web 仍会只读补充旧版报告；因此旧 HTML 可能与兼容显示的问题数不同。新报告记录 release_version、engine_sha256、schema_sha256、model_fingerprint、依赖版本及输入哈希；这些是追溯依据，不代表物理精度已校准。

## 7. 计算口径

| 指标 | 计算方式 | 不可混淆的含义 |
| --- | --- | --- |
| Die 面积 | 宽 × 高 / 10⁶ | DRAM 抽象平台不展示内部面积 |
| 模块占地 | 本层模块矩形并集，与 Die 边界求交 | 重叠不是重复加面积；重叠/越界另报问题 |
| 预留面积 | TSV、禁布区、显式通道的矩形并集并裁剪 | HB 当前不计独立占地；金属面积不直接扣到此项 |
| 有效区占用率 | 预留区外模块占地 / (Die 面积 − 预留面积) | 不等于标准单元利用率 |
| 最低模块面积 | 标准单元面积 / 目标单元利用率 + 硬宏面积 | 依赖真实面积输入和目标值校准 |
| 实际单元利用率 | 标准单元面积 / (模块外框面积 − 硬宏面积) | 面积未知时不能仅凭外框得出真实利用率 |
| 剩余可布局面积 | Die 面积 − 预留面积 − 预留区外模块占地 | 还需考虑形状、通道和连续可用空间 |
| 总功耗 / 余量 | 模块输入功耗之和 / Die 预算减总功耗 | 任一必需功耗未知则合计未知；不根据工作负载仿真功耗 |
| 金属 / 轨道面积 | 各段 Σ(线数 × 线宽或 pitch × 段长) | 多金属层投影面积不能等同 Die 占地 |
| 金属层容量 | floor(网格横向尺寸 / pitch × 可用比例) | 逐层检查，别的层空闲不能抵消本层超载 |
| 峰值拥塞比 | 所有金属层和网格的需求/容量最大值 | 不是实际详细布线的拥塞签核 |
| 通道容量 | 完整线束在同截面同时占用的轨道数与容量比较 | 不按连接在通道内的长度折减线数 |
| TSV/HB 信号预算 | 按相关相邻接口、全部所属 Core/区域汇总 | TSV 与 HB 分组，不能只取首个区域；多层路径逐接口计数 |
| 全部接口需求 | 信号 + 电源 + 地 | 未提供任一项时不得把合计显示为完整已知值 |
| 供电需求 | 功耗/电压；底层入口还含向上负载 | 端口能力只是预算，不是 IR drop/电迁移结果 |
| 延迟估算 | 输入系数 × 平面路径长度和跨层数，再加权 | 加权总和不等于模型执行时间；未校准时只可作相同口径比较 |

线宽和 pitch 来自输入金属层，路由按允许层和预算分配。程序没有根据电阻、电容、频率、信号完整性自动选出合格线宽。

路径为模块边缘端口的 Manhattan 估算，绑定通道时经过通道中心线。当前尚未完成所有障碍绕行、引脚分配、真实层间过孔、电气校验；显示横平竖直不代表路径已通过物理实现检查。

## 8. 自动寻优的实际能力

求解组件为 Google OR-Tools CP-SAT。它在离散网格上选择模块所属 Die 和位置，使用线长/跨层或延迟的代理目标。允许层、固定模块、同层组、边界、不重叠、间距、通道和部分已知预算形成约束；候选随后使用统一评估器复核。

模块尺寸、TSV 区域、供电端口固定，不自动调整。缺失功耗和接口容量不会神奇变成完整约束。具体目标、权重和边界以每次 `methodology.optimization` 与候选求解字段为准。

- `OPTIMAL`：当前离散代理模型中已证明最优，不代表真实物理布局全局最优。
- `FEASIBLE`：找到方案，但尚未证明该模型最优。
- `UNKNOWN` / 时间耗尽：不能据此判断没有可行方案或已达到最大方案数。
- 排除既有方案后得到 `INFEASIBLE`：仅说明当前离散约束下剩余空间已穷尽。

候选根据实际模块 ID、Die、坐标和尺寸去重；不靠修改编号制造不同方案。相邻网格位置不同也属于不同候选，尚未实现“结构上显著不同”的多样性阈值或 Pareto 前沿筛选。

## 13. 交付验收与常见排查

### 13.1 接收人员验收

- 核对程序与 `_internal` 完整，工程在独立目录；阅读验证记录并重新运行检查。
- 启动页面，载入测试工程，确认当前项目、工艺和结果位置。
- 导入/编辑双文件，修改一个模块位置，观察布线与资源重新计算；确认草稿未自动落盘。
- 故意制造重叠或容量不足，确认问题能显示并定位。
- 执行一次保存，检查 input、resolved-input、run、JSON、YAML、HTML 文件与页面路径一致。
- 请求多个候选，检查等待/完成状态、布局差异及无自动历史写入；检查当前/选中/全部保存范围、同批次独立目录、派生关联及部分失败重试。未应用 YAML 时必须阻止保存。固定全部模块后不会填充重复方案。
- 选择至少两个历史结果对比，未知值不按零计算；原历史快照未被改写。
- 对照待完善清单明确后续负责人；不要仅凭“运行成功”签收为物理实现准确。

### 13.2 排查表

| 现象 | 首先检查 |
| --- | --- |
| 页面打不开 | 入口是否正在运行、端口是否占用、`_internal` 是否缺失 |
| 目录选择返回 404 | 是否直接启动了 Engine，而不是 `Resim.exe serve` |
| 工程载入失败 | 两份 YAML 是否齐全，版本、引用、stack 是否有效；查看服务输出 |
| 功耗/TSV 合计未知 | 是否缺模块功耗、电源/地 TSV、pitch、容量或预算，不要补成 0 |
| 线面积为 0 / 拥塞未知 | 是否只输入接口预算而没有细分模块连接；已定义连接数量是否为 0 |
| 方案数不足 | 搜索时间、固定约束、可行空间和求解状态；不要人为复制布局补数 |
| 页面与旧 HTML 问题数不同 | 0.11 及更早历史仍有兼容差异；0.12 新报告应一致，检查 assessment_scope 与版本 |
| 不知道结果在哪里 | 到结果管理查看实际目录；外置输出不一定在项目 runs 下 |
| 更新脚本拒绝进程 | 核查程序完整路径与 HTTP 请求队列；TCP PID 4 不能直接当作 Resim PID |
| 新机器无法重建引擎 | 检查 Python 3.13、锁定依赖、C# 编译器及 build.py 输出；按 DEVELOPMENT.md 从新目录构建 |
