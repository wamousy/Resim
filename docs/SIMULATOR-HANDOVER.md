# Resim 模拟器交接文档

本文用于把当前 Resim 的源码、运行程序、工程数据和维护责任交给下一位开发者。它记录稳定事实、检查顺序和已知边界，不保存每次临时测试的完整输出。

## 1. 当前交付组成

```text
工作区/
├─ Resim/
│  ├─ app/          可直接运行的 Windows 发布包
│  ├─ src/          完整可维护源码、测试和工具
│  └─ docs/         三份主文档及机器契约
└─ ResimProjects/   用户工程、参考资料和运行历史
```

当前架构采用浏览器前端、Python 计算引擎和 Windows Host。发布包可以独立运行；开发和重建以 `src` 为准。

## 2. 权威来源

发生不一致时按以下优先级处理：

1. `src/backend/` 与 `src/frontend/` 是实现的源码来源。
2. `src/tests/` 定义已经自动化验证的行为。
3. `docs/contracts/` 定义当前导出的输入与 API 契约。
4. `app/` 是发布产物，应由源码构建产生。
5. `ResimProjects/*/inputs/` 是各工程当前输入。
6. `runs/` 是历史快照，不反向覆盖当前输入。

不要把 `app/_internal` 中的冻结文件当作源码编辑。不要根据旧运行报告推断当前算法仍完全相同。

## 3. 已具备的能力

- 新版双 YAML 输入及 Pydantic 结构、引用和一致性校验；
- 多 die、多 core、模块、端口、连接、预留区和堆叠关系；
- 模块越界、同层重叠、间距、TSV 禁布区和层间接口检查；
- 面积、线长、金属资源、拥塞、TSV/HB、功耗与供给的架构级估算；
- 2D/3D 展示、core 下钻、单层正反面和对象定位；
- 手工布局编辑及自动分区/布局候选；
- 当前方案保存、命名历史、输入快照、结果对比和导出；
- 工程打包与解包、旧工程 ID 别名和外部结果目录；
- 从源码构建 Windows 发布包并执行前端、后端和集成验证。

## 4. 当前工程管理约定

所有正式工程应包含：

- `project.json`
- `inputs/chip-architecture.yml`
- `inputs/technology.yml`
- `README.md`
- `run.ps1`
- `references/`
- `runs/`

工程输入必须使用 UTF-8。正式工程不应依赖已删除的临时目录。清理外部结果时，同时处理工程中的索引记录，否则页面加载最近结果可能返回 `Unknown run`。

`ResimProjects/_references` 保存多个工程共用的来源文件，`_templates` 保存新版工程模板；它们不属于可直接运行的工程。旧 `_project-aliases.json` 仅用于兼容历史编号。新版 Windows 程序改用系统互斥锁，不再生成 `.resim-store.lock`；停止旧版程序后可清理遗留锁文件。

## 5. 模型边界

Resim 当前属于架构级和早期物理规划工具，不是完整 EDA 签核工具。以下能力仍依赖外部数据或后续实现：

- 标准单元、SRAM、DMA、Tensor 等模块的目标工艺面积和能耗标定；
- 基于活动率、操作次数与时间的动态功耗；
- 详细时钟树、详细布线、提取后 RC 和静态时序分析；
- IR drop、电迁移、热耦合和机械应力；
- TSV/HB 的真实 pitch、冗余、电源地比例和制造禁布规则；
- DRAM 封装内部结构和控制器/通道的完整时序模型；
- OpenROAD 或其他物理实现工具的闭环校准。

因此报告中的 `unknown` 是有效状态。缺失数据不能填零，也不能根据剩余面积推断一定可实现。

## 6. 重点风险

### 6.1 外部运行结果

运行记录可以指向工程目录之外的结果位置。删除外部目录后，残留索引会出现在历史列表，但无法加载结果。工程列表和历史读取应对这种情况给出局部错误，不能让整个工程无法打开。

### 6.2 大型工程前端负载

数百模块和大量连接的报告可能达到数 MB。前端应延迟渲染长表、分页显示问题和间距记录，并避免为隐藏面板创建全部 DOM。

### 6.3 自动布局精度

当前优化器依据抽象矩形、离散网格和输入资源约束工作。候选通过当前检查只代表模型内可接受，不代表完成详细物理实现。

### 6.4 输入兼容

旧的单 YAML、description 中的堆叠兼容块及旧工程 ID 可能仍存在于历史文件。兼容读取不得在未保存时改写原历史；新保存内容统一输出当前原生字段。

### 6.5 运行事务

运行失败时应保留输入快照和明确错误。写入中断后不能把半成品标记为 `completed`。涉及工程输入、运行索引和外部结果的修改必须继续使用锁和原子写入。

## 7. 接手后的首次检查

1. 确认 `Resim/app/Resim.exe` 与 `Resim.Engine.exe` 都存在。
2. 启动程序并访问 `/api/health`，确认版本和工程目录正确。
3. 使用一个小工程运行 `validate` 和 `evaluate`。
4. 打开一个多层工程，检查 3D、单层视图、TSV/HB 和结果历史。
5. 从源码启动独立端口，避免与安装版共用进程和测试工程。
6. 运行完整验证，确认前端源码与发布副本一致。
7. 检查 `docs/contracts` 与当前 Schema/API 是否匹配。
8. 检查工程运行记录是否存在指向已删除外部目录的索引。

## 8. 修改与发布检查表

发布前：

- 明确改动影响的输入、计算、API、前端和历史兼容范围；
- 完成相关单元测试和真实工程往返测试；
- 重新生成 Schema 与 OpenAPI；
- 同步前端发布副本；
- 构建全新暂存 `app`；
- 对同一暂存构建运行完整验证；
- 关闭或识别正在使用旧发布目录的进程。

发布后：

- 核对两个 EXE 和构建清单；
- 检查健康接口与默认工程根目录；
- 实际打开工程并保存一次评估；
- 检查输入快照、结果目录和历史读取；
- 更新三份主文档中受影响的说明；
- 将详细测试日志放入发布归档，不长期堆积在 `docs` 根目录。

## 9. 后续开发优先级

1. 让损坏或丢失的单条历史记录不再阻止工程整体打开。
2. 为大型报告增加更严格的按需传输与渲染。
3. 补充可校准的模块面积、能耗和互联延迟模型。
4. 加强运行事务、任务取消、进度恢复和异常回收。
5. 建立 OpenROAD/LEF/网表结果回传及模型校准流程。
6. 增加 TSV、供电、热和封装约束，而不把未知参数伪装成确定值。

## 10. 文档维护规则

- 用户操作只写入 `SIMULATOR-USER-GUIDE.md`。
- 构建、源码结构、API 和测试写入 `SIMULATOR-DEVELOPMENT-GUIDE.md`。
- 当前状态、风险、兼容和接手检查写入 `SIMULATOR-HANDOVER.md`。
- Schema 与 OpenAPI 保存在 `docs/contracts/`，由程序生成。
- 临时验证日志不作为长期文档；`verify.mjs` 默认写入 `src/tools/.artifacts/`，并拒绝写入 `docs/`。发布时只保存必要摘要或移入独立发布归档。

### chipS 图纸补充（2026-09-30）

已支持图纸参考记录与只有线数、没有速率的连接。chipS 输入中的 `reference_groups` 为参考口径，不能与子模块面积重复相加。图纸工艺节点未提供；现有 Nangate45 连线资源不代表图纸模块已在该工艺校准。原图内若出现前后版本不一致，保持来源与待核对注释；不能把“Cell Number”的万单元数当作 W 功耗。

当前补充保留原来的 16 核布局及 800 mm²/logic die。L die 中央模块命名、新旧 HB/TSV 总量、X 共享区域统计与方向不明的连接，需要按用户确认逐项更新，不能根据总量平均分配未知线路。参考面积大于现有缩放占地时，报告会提示实现难点，不会自动扩大片内区域掩盖问题。
